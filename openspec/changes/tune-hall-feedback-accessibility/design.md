# Local feedback on flat screens and in stereo

## Tuning and preferences

Put per-effect enabled flags, numeric defaults, curves and relative asset names in a client-only table in the loose hall Lua. The existing world script is client-only and already ships in the Web manifest. Use the existing client content loader if moving the table into its own script later. Keep user overrides in a versioned feedback record alongside the existing engine saves. The native menu and Web dialog edit the same fields. Web persists the record through the existing IDBFS sync. Local settings never travel in room commands. Honor a first-run system reduced-motion preference where available and let explicit saved choices win. [Content loader](../../../src/content.c) · [Loose-file packaging](../../../tools/package.py) · [Native settings](../../../src/settings.c) · [Browser persistence](../../../web/hall.js)

**Motion** scales decorative pose excursions and UI movement. Zero selects still state shapes. **Detail** scales transient snow flecks, stamps and trails, with zero drawing none. **Sounds** sets optional feedback gain through the engine bus and allows a muted run. **Marks** controls transient personal hit marks. **Contrast** sets the outline treatment. **Captions** adds short, localized text or shape equivalents. **Haptics** defaults to zero and scales an optional supported controller pulse. Each effect also has an individual authoring switch. Ownership, duplicate suppression, hard budgets and essential state text continue to work at every setting. Keep the current camera stable across the proposed default layers. No post-processing passes are required for these proposals.

## One effect, two eyes

Flat native and Web already use different HUD render paths. Generate the meaning, timing and shape once in the hall Lua and render through the appropriate existing path. Immersive WebXR draws each eye to the XR framebuffer. Important confirmations belong at the target and slow status beside the tracked tool, readable with either eye. A DOM-only label cannot meet this requirement. Keep the exact eye pose, projection and controller ray supplied by the runtime, including on rocket fire. Actuator calls are optional and failures are silent. End outstanding pulses when the XR session closes. [Stereo bridge](../../../web/xr.js) · [Client rendering](../../../src/client.c)

## Keep a busy hall readable

Reserve essential shapes separately from decorative sprites. The proposed cap of 48 additional sprites for desktop and 24 for touch/XR applies to the whole view across eight players. Existing ambient snow is part of the measured baseline. Evaluate visible effects once per game frame and render that list to both eyes. Reuse engine sprites and burst emitters, avoid per-shot lights and allocations, and discard the oldest distant decoration first. A pool entry can be reused immediately on a pocket change. Coalesce repeated cues, budget optional voices in the client and submit to the engine’s existing mixer. Set its listener from the real camera and pocket before spatial playback. Measure effects-off and effects-on on the same scene with eight players, the range active and all 24 doors due. Save median and p95 frame times, dropped optional cues and the device and renderer. Compare with the existing release targets of 60 fps on desktop, 30 fps on mobile and 72 Hz on Quest 3. The software-renderer baseline is diagnostic only. Verify with a physical Quest and phones before making claims about comfort, speaker balance or sustained frame rate.
